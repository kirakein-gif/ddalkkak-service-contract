# 시스템 설계 초안

## 핵심 원칙

### 1. 규칙과 문서 생성을 분리

- Rule Engine: 계약방법·금액구간·절차·체크리스트 판정
- Template Engine: 품의서·공고문·통지서 등 문서 생성

### 2. 법령 데이터와 코드를 분리

금액기준이나 규정이 바뀌었을 때 프로그램 전체를 수정하지 않고 규칙 데이터만 갱신할 수 있도록 구성합니다.

### 3. 근거 추적 가능

모든 판정 결과에 다음 정보를 함께 저장할 수 있도록 설계합니다.

- 적용 규정명
- 조문·장·절
- 기준일
- 규칙 버전
- 담당자 확인 여부

### 4. 외부 시스템은 읽기 중심

나라장터 OpenAPI에서 공고·개찰·낙찰·계약정보를 조회합니다. 실제 공고 등록·낙찰결정·전자계약 체결은 초기 버전에서 자동 수행하지 않습니다.

### 5. AI는 선택 기능

AI 서류검토는 1.0 필수기능이 아닙니다. 추후 기관 보안정책과 사용 가능한 AI 환경이 확정되면 별도 모듈로 연결합니다.

## 예정 모듈

- `app/rules`: 계약 판정
- `app/services/g2b.py`: 나라장터 API
- `rules/`: 규칙 데이터
- `templates/`: 문서 템플릿
- `docs/`: 근거자료 및 설계문서
- `tests/`: 사례 기반 회귀테스트

## 테스트 전략

실제 완료 계약을 익명화한 테스트 케이스로 저장하고, 규칙 변경 시 기존 계약의 판정 결과가 의도치 않게 달라지는지 자동검증합니다.
