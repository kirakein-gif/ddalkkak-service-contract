# 학교 용역계약 1차 분기 설계

> 상태: 설계 초안. 아직 실제 계약 판정에 사용하지 않는다.

## 입력 0: 기준일

모든 계약판정은 반드시 **계약/공고 예정일**을 받는다.

이유:
- 지방계약법령·예규가 개정될 수 있음
- 과거 공고 샘플의 예규 번호를 그대로 현재 계약에 적용하면 안 됨
- Rule Engine은 effective_from / effective_to로 규칙 버전을 선택해야 함

---

## 입력 1: 학교업무 유형

- TRANSPORT: 차량임차·통학버스
- TRAVEL: 수학여행·현장체험학습 위탁
- PROGRAM: 방과후·늘봄·교육프로그램 운영
- FACILITY: 시설 유지관리·법정점검
- SIMPLE_LABOR: 청소·방역·단순 반복용역
- GENERAL: 기타 일반용역
- TECHNICAL: 기술용역/PQ/설계·감리 (후속모듈)

---

## 입력 2: 기본 금액

반드시 구분 저장:

- 예산액
- 추정가격
- 부가가치세
- 기초금액
- 총액/단가 여부

**계약방법 판정의 기본 금액축은 추정가격**으로 사용한다.

---

## 1차 의사결정 트리

### STEP 1. 기술용역인가?

YES
→ 일반 학교용역 엔진에서 분리
→ 기술용역/PQ 모듈로 이동

NO
→ STEP 2

### STEP 2. 품질·규격 평가가 핵심인 용역인가?

대표 후보:
- 수학여행/현장체험학습
- 방과후/늘봄 프로그램 운영
- 제안서 평가가 필요한 위탁사업

YES
→ 2단계 입찰 검토 플래그
→ 시행령 제18조 적용 가능 여부
→ 단순노무용역 제외 여부 확인
→ 제안서 평가 흐름 생성

NO
→ STEP 3

### STEP 3. 추정가격 2천만원 이하인가?

YES
→ 1인 견적 수의계약 가능 플래그
→ 다만 의무가 아니라 '가능'임을 표시
→ 특별한 계약상대자 요건/내부기준 확인
→ 필요 시 2인 이상 전자견적 선택 가능

NO
→ STEP 4

### STEP 4. 2인 이상 견적 수의계약 금액범위인가?

YES
→ 지정정보처리장치 전자견적 흐름
→ 지역제한/업종/중소기업/직접생산 등 참가자격 구성
→ 복수예가/계약상대자 결정기준 설정

NO
→ STEP 5

### STEP 5. 경쟁입찰

→ 일반경쟁/제한경쟁 검토
→ 지역제한 가능 여부
→ 업종제한
→ 실적제한 가능 여부
→ 적격심사/2단계/협상 등 낙찰방식 분기

> 2인 이상 견적 수의계약의 정확한 현행 금액 상한과 예외는 예규 제372호 원문 기준으로 규칙 테이블화한 뒤 확정한다.

## 업무유형별 추가 질문

### TRANSPORT
- 통학/현장체험/행사 중 무엇인가
- 1회성/연간인가
- 차량대수
- 승차정원
- 운행횟수
- 총액/단가
- 운전원 포함
- 동승보호자 포함
- 운행노선
- 요구 차량연식
- 지역제한

### TRAVEL
- 국내/국외
- 인원
- 박수
- 항공 포함
- 숙박 포함
- 식사 포함
- 차량 포함
- 입장료 포함
- 안전요원 포함
- 제안서 평가 필요
- 평가위원회 일정

### PROGRAM
- 대상학생
- 운영기간
- 프로그램 수
- 강사 포함
- 교재비/재료비 포함
- 실제인원 정산 여부
- 제안서 평가 여부

### FACILITY
- 시설종류
- 법정점검 여부
- 요구 면허
- 기술인력 요건
- 점검주기
- 보고서 제출
- 손해배상/보험 요건

### SIMPLE_LABOR
- 청소/방역/경비 등
- 인원
- 기간
- 근로시간
- 노무비 비중
- 최저임금/보험/노무 관련 항목

## 결과 화면 구조

판정 결과는 한 줄 결론으로 끝내지 않는다.

### 1. 추천 처리경로
예: 2인 이상 견적제출 수의계약

### 2. 판정 근거
- 적용 법령/예규
- 조문/장절
- 시행일
- 판정에 사용한 입력값

### 3. 확인 필요
자동판정이 불가능하거나 담당자가 확인해야 할 항목

### 4. 다음 업무
- 품의 작성
- 과업지시서
- 공고문
- 나라장터 입력
- 개찰
- 계약상대자 확인
- 계약체결

### 5. 문서 생성
단계에 필요한 서류만 노출

---

## 중요한 설계원칙

Rule Engine 결과는:
- 확정(법령으로 기계판정 가능)
- 조건부(추가 입력 필요)
- 검토필요(담당자 판단)

3단계로 상태를 구분한다.

AI가 없어도 이 구조만으로 학교 계약업무의 상당 부분을 자동화할 수 있다.
