# 용역계약 업무 흐름

> 이 문서는 딸깍 용역계약의 기준 업무 흐름을 정의하기 위한 초안입니다.
> 실제 완료된 용역계약 사례를 기준으로 단계·문서·판단 기준을 검증해 확정합니다.

## 전체 흐름

1. 사업계획·예산 확인
2. 과업내용 및 계약조건 정리
3. 추정가격·기초금액 관련 자료 확인
4. 계약방법 결정
5. 참가자격·지역제한·실적제한 등 검토
6. 내부 계약방법 결정 품의
7. 나라장터 공고 또는 견적제출 안내
8. 공고내용 검증
9. 개찰
10. 낙찰자 결정 또는 적격심사
11. 계약체결 대상자 서류 확인
12. 계약체결
13. 이후 변경계약·이행·검사·대가지급 단계 연계

## 단계별 설계표

| 단계 | 사용자가 하는 일 | 시스템이 도울 일 | 최종 확인 |
|---|---|---|---|
| 계약조건 입력 | 용역명·금액·기간·종류 등 입력 | 필요한 추가 항목 요청 | 담당자 |
| 계약방법 검토 | 조건 확인 | 규칙엔진으로 적용 가능 절차 제시 | 담당자 |
| 근거 확인 | 법령·예규 확인 | 적용 근거와 기준일 표시 | 담당자 |
| 품의 | 내부결재 문서 작성 | 문안 자동생성 | 담당자 |
| 공고 | 나라장터 입력 | 공고문·입력값표 생성 | 담당자 |
| 개찰 | 결과 확인 | 나라장터 API 조회·정리 | 담당자 |
| 낙찰 | 평가 및 결정 | 계산·체크리스트·문서 생성 | 담당자 |
| 계약 | 제출서류 확인 | 계약 관련 문서 생성 | 담당자 |

## 첫 구현 대상

가장 단순하고 빈도가 높은 용역계약 1건을 선정해 다음을 역설계합니다.

- 최초 품의문
- 공고 또는 견적제출 안내
- 나라장터 입력항목
- 개찰 결과
- 낙찰자 결정 문서
- 계약체결 문서
- 당시 적용한 법령·예규 및 기관 기준

이 사례를 통과시키는 것을 0.1 버전의 완료 기준으로 합니다.
